# Deploying

Production follows `OD-08` and `OD-09`: the database on Neon, the API on Render, the client on Vercel, and photos on Cloudinary. Env vars are listed in PRD section 13.

## 1. Database (Neon)

1. Create a project and copy its pooled connection string.
2. That string is `DATABASE_URL`. Migrations run on every Render build (`prisma migrate deploy`), so there is no manual step.

## 2. Photos (Cloudinary)

Copy the `CLOUDINARY_URL` from the dashboard (`cloudinary://key:secret@cloud`).

## 3. API (Render)

1. New, then Blueprint, then this repo. Render reads `render.yaml`.
2. Fill the values marked `sync: false`:

   | Var | Value |
   |---|---|
   | `DATABASE_URL` | from Neon |
   | `CLIENT_ORIGIN` | the Vercel URL, for example `https://andropedia-recruitment.vercel.app`, with no trailing slash |
   | `WHATSAPP_COMMUNITY_URL` | the live community invite link |
   | `CLOUDINARY_URL` | from Cloudinary |
   | `ALLOWED_EMAIL_DOMAIN` | blank (off, `OD-04`) or a domain such as `srmist.edu.in` |

3. `ADMIN_EXPORT_TOKEN` is generated by Render. Copy it from the service's Environment tab. Keep it private.
4. Check `https://<api>.onrender.com/api/config`. It should return `recruitmentOpen` and `whatsappUrl`.

The free plan sleeps after 15 minutes idle, and the first request after that takes up to a minute. Use a paid instance for the recruitment window.

## 4. Client (Vercel)

1. Import the repo and set the Root Directory to `client`. Vercel installs the npm workspaces from the repo root.
2. Set these env vars:

   | Var | Value |
   |---|---|
   | `VITE_API_BASE_URL` | the Render URL, for example `https://andropedia-recruitment-api.onrender.com` |
   | `ALLOWED_EMAIL_DOMAIN` | the same value as on Render, so step 01 blocks the same emails the server rejects |

3. Deploy. `client/vercel.json` sends every path to `index.html`, so refreshing `/apply/you` works.
4. If the Vercel URL is different from `CLIENT_ORIGIN`, update `CLIENT_ORIGIN` on Render.

Client env vars are read at build time. Redeploy the client after changing them.

## Operations

- **Close recruitment (`LND-08`):** set `RECRUITMENT_OPEN=false` on Render and let it restart. Every Apply now button becomes the closed message, `/apply/*` routes go home, and a late submit gets the closed message. Set it back to `true` to reopen.
- **Export applications (`ADM-01`):**

  From the repo, with `ADMIN_EXPORT_TOKEN` in `.env` or the environment:

  ```
  npm run export:csv -- https://<api>.onrender.com
  ```

  It saves `exports/applications-<date>-<time>.csv`, a folder git ignores because it holds applicants' personal data. With no URL it uses the local API. Without the repo, use curl:

  ```
  curl -H "Authorization: Bearer $ADMIN_EXPORT_TOKEN" https://<api>.onrender.com/api/admin/applications.csv -o applications.csv
  ```

  The file is UTF-8 with a BOM and CRLF line endings, so Excel shows names and multi-line answers correctly. In Google Sheets, use File, Import, Upload. Cells that start with `=`, `+`, `-` or `@` begin with `'`, as `ADM-01` requires; phone numbers (`'+91…`) show the apostrophe too.

## Before launch (PRD section 15)

- Replace `TODO_CONTENT` in `shared/copy.ts`: `about.body` and `footer.body` (`LND-09`, Instagram and contact links).
- Open the WhatsApp link on an Android phone and an iPhone.
- Run the `NFR-04` device checks on a small Android, a large Android and a notched iPhone.
