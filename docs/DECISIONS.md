# Decisions

One line per decision the PRD was silent on.

- Phase 1: PRD moved from repo root to `docs/PRD.md` to match PRD section 13 and CLAUDE.md.
- Phase 1: `shared/` is consumed as TypeScript source (`main: ./index.ts`); no build step. Client uses Vite, server uses tsx.
- Phase 1: Only phase 1 dependencies installed. react-router, react-hook-form, motion (client) and prisma, multer, sharp (server) arrive with the phase that uses them.
- Phase 1: Tailwind pinned to v3 because DSN-06 specifies `tailwind.config.ts` theme overrides; zod pinned to v3.
- Phase 1: `phone` in `youSchema` accepts 10 digits or `+91` prefixed and outputs `+91XXXXXXXXXX`, so parsed output equals the PRD 8.2 payload; the transform is idempotent.
- Phase 1: Step schemas carry their own cross-field rule (`domainSchema` pref2 differs, `usSchema` otherClubs required); `applicationSchema` repeats both on the merged shape.
- Phase 1: Long text answers use `longTextMin`/`longTextMax` from LIMITS; `rememberUs` is capped by word count (30) instead of the long text min.
- Phase 1: `scripts/check-design.sh` extends the PRD pattern with pill patterns (`rounded-[`, `pill`, per-corner `rounded-t-full`), `conic-gradient`, `glassmorphism`, `bento`, and any `border-radius` above 4px; it scans `client/src` and `client/index.html`, sets `LC_ALL=C.UTF-8` so `grep -P` works on Git Bash, and exits 2 if grep itself fails.
- Phase 1: Root `dev` script uses `concurrently` because `&` is not parallel on Windows cmd.

## Phase 2: Backend

- Prisma 7 (stable 7.10): `prisma.config.ts` holds the datasource URL, the client is generated to `server/src/generated/prisma` (gitignored, regenerated by `npm run typecheck`) and connects through `@prisma/adapter-pg`. `prisma` itself is a devDependency. `npm audit` reports advisories in the Prisma CLI's own tree (deepmerge-ts, lodash, mysql2); none ship in the running server, and the only offered fix is a major downgrade.
- The PRD's one-line enums in 8.3 are not valid Prisma syntax, so they are expanded one value per line. Names and values are unchanged.
- Routes depend on a `Db` interface (`server/src/db.ts`), with Prisma behind it (`db.prisma.ts`). Supertest suites run against an in-memory fake that enforces the same unique constraints; `server/test/db.prisma.test.ts` runs the full flow against real PostgreSQL when `TEST_DATABASE_URL` is set (separate from `DATABASE_URL` because it truncates tables).
- Honeypot placement: `website` is checked after the rate limiter and the closed-round check, and before schema validation. A filled honeypot returns a fake `201 { id }` (random uuid) and stores nothing, so bots get no validation feedback. `website` stays in `applicationSchema` (`max(0)`) as a backstop and is stripped before storage.
- Rate limit buckets: three separate in-memory `express-rate-limit` instances (check 30, photo 20, submit 5, per IP, 1 hour window, values in `RATE_LIMITS`). They count every request to the route, including 400s. In production `trust proxy` is set to 1 so the real client IP is used behind one proxy; that must match the host's proxy depth. In-memory counters reset on restart and are per process; swap the store if the API ever runs on more than one instance.
- Rate limit risk to watch: students on one campus network share a public IP, so 5 submits per hour per IP could block a lab full of applicants. The limits are the PRD's; if this bites, raise `RATE_LIMITS.submit` in `shared/constants.ts`.
- Error format: every non-2xx is `{ errors: [{ path, message }] }`, one error per field path (first message wins). 409 also carries `{ field }` as API-04 requires. Statuses: 400 validation, 401 admin token, 403 closed round or plain HTTP in production, 404 unknown route, 409 duplicate, 413 body over 100kb, 429 rate limit, 500 unexpected.
- Admin auth returns 401 (not 403) for a missing or wrong token; with `ADMIN_EXPORT_TOKEN` unset the export is unreachable. Comparison is constant time (sha256 digests, `timingSafeEqual`). Startup fails if the token is under 32 characters.
- Three server messages were added to `copy.ts` as `// added`: `err.server`, `err.rateLimit`, `err.unauthorized`. The copy test lists them separately from the PRD table.
- Constants added to `shared/constants.ts`: `RATE_LIMITS`, `JSON_BODY_LIMIT`, `PHOTO_MIME_TYPES`.
- HEIC: sharp's prebuilt libvips cannot decode HEVC (verified with a real HEIC: `bad seek`, `HEVC ... not built in`). HEIC and HEIF are decoded to JPEG with `heic-convert` (WASM libheif), then run through the normal sharp pipeline (auto-rotate, strip metadata, 1080px, WebP q80). Everything else goes straight to sharp. File type is sniffed from bytes with `file-type`; the client's mime type and filename are ignored. Undecodable or truncated images return 400 `err.photoType`.
- Photo URLs: the local driver stores and returns a path (`/uploads/<id>.webp`); routes make it absolute from the request (`absoluteUrl`) for the upload response and the CSV. Cloudinary URLs are already absolute. The app serves `/uploads` only with the local driver, with `Cross-Origin-Resource-Policy: cross-origin` so the client origin can embed the images.
- Cloudinary driver uses the signed upload REST API over `fetch` (no SDK). It is covered by a mocked-fetch test only and has not been run against a live Cloudinary account.
- Uploads are not blocked when recruitment is closed (the PRD only closes check and submit).
- CSV column order (ADM-01): `id, createdAt, status`, then the PRD 8.2 payload order with `photoId` replaced by `photoUrl` (name, registerNumber, email, phone, department, section, domainPref1, domainPref2, aboutYou, whyDomain, skills, techStack, outsideAcademics, whyAndropedia, oneYearVision, workUrl, portfolioUrl, achievements, photoUrl, hoursPerWeek, responsibility, inOtherClub, otherClubs, clubShouldProvide, rememberUs), then derived `admissionYear` last. `inOtherClub` is exported as `yes`/`no`. Rows are oldest first.
- CSV safety and format: cells starting with `=`, `+`, `-`, `@` get a leading `'` (also tab and carriage return). This includes every `+91...` phone number, as ADM-01 specifies. RFC 4180 quoting, CRLF line ends, UTF-8 BOM so Excel reads non-ASCII names. `Cache-Control: no-store`. Phase 9 should confirm this opens cleanly in Excel and Google Sheets.
- `ALLOWED_EMAIL_DOMAIN` (SEC-05) is enforced on submit server side (400 on `email`). The client half comes with the form steps.
- Request logging (SEC-02): method, path without query string, status, duration. Enabled by `src/index.ts`, off in tests.
- Env loading: `process.loadEnvFile('../.env')` in the server entry and in `prisma.config.ts`; real environment variables take precedence. Prisma migrations are run with `npm run db:migrate -w server`.
- ESLint: names starting with `_` are allowed to be unused.

## Phase 3: Landing page

- `landing_page_idea.md` does not exist. The closest file, `hero page idea.md`, is a prompt for a different site ("Mainframe" agency): video background, nav menu, blurred text, `backdrop-blur` overlay, pill buttons, third-party font CDN. Every one conflicts with PRD section 4 (LND-01 no nav) or the CLAUDE.md design bans, so none of it was used; the layout follows PRD section 4 and DSN-02 to DSN-10.
- DSN-03 token change: `--red` #E5372A to #E9402F. Ink text on the old red was 4.38:1, under AA 4.5:1 for 18px button text (caught by axe). New value is 4.68:1 with ink. Visually near identical.
- The red `|` separators in hero lines 3 and 4 are about 3.5:1 on paper. They are punctuation, not words, and pass the 3:1 large-text bar from 430px up; at 360px they are 18px. Kept as the brief's accent.
- Hero line 2 sits on one tilted yellow block (inline-block), not an inline highlight. An inline background with 0.9 line height painted over the bottom of each previous line.
- Hero and header use up to 1280px (`max-w-screen-xl`, PRD allows a wider hero); every other section is capped at 720px. At 1280x800 this keeps all four lines and Apply now above the fold.
- Accent color for hero separators and the section-title underline: `--red` (the primary button color). Line 2 highlight: `--yellow` (DSN-03 "highlights").
- Section color bands: What we do on yellow, closing CTA on ink (focus ring switches to paper there via `--focus`), everything else on paper.
- New copy, tagged `// added`: `brand.name` (wordmark), `modal.close` (accessible name of the close icon), `footer.body` (`TODO_CONTENT`, LND-09 P2, needs owner). The 404 page's home button reuses `nav.back`.
- Motion is CSS only (transitions and keyframes in `styles/motion.css`), no Motion library on the landing page, to keep the initial bundle small (NFR-01). Build: 80 KB JS gzipped.
- Domain row interaction: mouse hover floods while the pointer is over the row; touch and pen press floods and holds 600ms after release so the tap is visible. Rows are not focusable (they are not controls), so keyboard users see no flood.
- The process stamp (final step) lands once, the first time the step is 60% in view (IntersectionObserver).
- Config (API-01) loads once per session. While loading, the Apply slot reserves 56px and shows nothing. If the API cannot be reached, the page falls back to open (the apply flow will surface the network error); the failure is not cached.
- Apply now's modal button navigates to `/apply/you`. Resuming at the first incomplete step from a draft (LND-07) comes with the shell in phase 4, as does the closed-state redirect of `/apply/*`. Until then `/apply/*` shows the 404 page.
- Vite proxies `/api` and `/uploads` to :4000 in both `dev` and `preview`, so local runs are same origin. Production still uses `VITE_API_BASE_URL`.
- Playwright (`npm run test:e2e -w client`) runs against the production build in the locally installed Chrome (`channel: 'chrome'`), at 360x640, 390x844, 430x932 and 1280x800. It is not part of `npm test` because it needs a browser.
- Lighthouse mobile (production build, real API): Performance 98, Accessibility 100, Best Practices 100. SEO 82 (missing meta description, which needs owner copy, and no robots.txt); SEO is not a phase 3 target.
